## 项目概述

《机动战士高达 SEED 激斗命运》（*Mobile Suit Gundam SEED: Battle Destiny*）是 **单人向第三人称锁敌 MS 动作** 游戏：玩家创建 **原创驾驶员 + 搭档**，以自然人或调整者身份加入 **地球联合 / 扎夫特 / 大天使号（三舰同盟）**，在 **C.E.71 / C.E.73** 双线中推进任务；战斗中与 **CPU 僚机** 协同，通过 **主/副兵装、格斗、SP/チャージ、ブースト** 高速交战；战役外以 **点数强化机体**、解锁 **技能与来宾机师**，并在周目后解锁 **Another Arc / EX / Hyper Boss Battle** 等终局内容。参战机体 **100+**。

本仓库目标是 **粉丝向精神复刻**：在 **不搬运官方资产、不拆包 Steam/官方安装包资源** 的前提下，用现代双平台工程 **对齐 Steam 版 REMASTERED（1857740）所呈现的系统与体验**；2012 PS Vita 原作仅作机制溯源与变更说明，**不以「仅复刻 Vita」作为验收终点**。

### 核心原则

| 原则 | 说明 |
|------|------|
| **玩法优先** | 先证明战斗 + 任务循环好玩，再铺 100+ 机体 |
| **数据驱动** | 机体、武装、任务、技能以外部数据描述，禁止硬编码内容 |
| **可替换资产** | 模型/动画/音频与数据解耦，占位资产可热更 |

## 一、战斗系统

### 1.1 设计定位与战斗节奏

战斗是 **单人 + CPU 僚机** 的第三人称锁敌 MS 动作：硬直短、推进快、SP 积攒与消耗频繁，整体为「高速割草 + 机体特性博弈」，而非拟真模拟或纯格斗对战。

复刻应以 **对齐 Steam REMASTERED（1857740）在战斗中的默认体验** 为首要目标：机制骨架与 Vita 2012 一脉相承，但 **锁敌模式、目标信息 UI、操作映射与帧率目标** 以 2025 Steam 版为准。

| 维度 | 目标 |
|------|------|
| 上手性 | 锁敌后一键射击/格斗，降低三维瞄准门槛 |
| 深度 | 兵装、装甲、换装、特殊射击驱动构筑与战术 |
| 节奏 | 短硬直 + 快回 SP/BOOST，鼓励积极进攻 |
| 协同 | 僚机指示体现小队作战，而非 1vN 无双 |

### 1.2 原作机制总览

#### 三大资源与基础行动

| 资源 | 作用 |
|------|------|
| **HP** | 机体耐久；归零击坠 |
| **SP ゲージ** | 必杀、チャージ行动资源 |
| **BOOST ゲージ** | 推进器热量；满槽 **オーバーヒート** 限制喷射 |

基础输入（以 REMASTERED TYPE A 为参考）：左摇杆移动；**ブースト**（跳跃/冲刺/急升/急降）；**主兵装 / 副兵装 / 格闘**；**ガード**（可移动）；**ロックオン** 切换锁定。锁敌时以目标为环绕轴，非锁敌时以自机为轴。

#### 锁敌战斗（ロックオン）

- 绝大多数射击与格闘在锁定下自动朝向目标。
- REMASTERED **スタンダード**：右摇杆左右循环敌机；上切重要目标；下切最近敌机。
- **クラシック**：按敌机种类循环（服务习惯原版玩家）。
- 烟雾、隐形等可 **打断锁定**；复刻版增加锁敌时 **PS 残量条、Down/无敌** 等状态图标。

#### 主兵装 / 副兵装

- 主兵装：核心输出；部分机体 **L2/R2 切换多主武装**。
- 副兵装：牵制、削甲、收尾（如バルカン、ミサイル、ファンネル）。
- **总弹数（総弾数）**：弹匣打空可装填，总弹耗尽则本场该武装不可用；地图 **补给集装箱** 可恢复。
- **チャージ射撃** 附带「主兵装瞬时装填」——慢装填武装的核心战术价值。

**特殊射击**：长按主兵装 **予測射撃**；**狙撃モード**；**マルチロックオン**（多目标分配）；单目标时 **多重ロック**（弹道集中）。

#### 格闘、SP / チャージ、ブースト

| 行动 | SP 消耗（约） | 概要 |
|------|---------------|------|
| チャージ射撃 | 1 目盛 | 强化射击 + 主兵装装填 |
| チャージ格闘 | 0.5 目盛 | 强化近战 |
| チャージブースト | 0.5 目盛 | 高速位移；可派生强化格闘 |
| SP アタック | ~50% | 机体固有 / 驾驶员固有；出撃前可选类型 |

SP アタック分 **机体固有** 与 **驾驶员固有**；特定组合可 **コンビネーション SP**（僚机联动，不消耗僚机 SP）。

ブースト中 BOOST 上升；满槽过热则无法喷射类行动。陆地/宇宙/水中等环境对机动上限有不同约束。

#### 僚机指示（パートナー指示）

| 指示 | 行为 |
|------|------|
| 格闘 | 积极近战 |
| 射撃 | 远程火力 |
| 防御 | 护卫、吸引火力 |
| SP | 适当时机释放僚机 SP |

无指示时僚机攻击最近敌人。僚机可再出击（击坠后随 HP 槽回复再上场）。

#### 变形 / 换装 / パージ

| 机制 | 限制 |
|------|------|
| **変形** | MS ↔ MA 等；通常无次数限制 |
| **換装** | 背包/形态切换（インパルス、ストライク系）；无次数限制 |
| **パージ** | 抛弃装甲/武装（シュラウド等）；**本战不可恢复** |

#### 特殊装甲与防御

- **ガード**：盾牌格挡；敌我均可形成盾墙。
- **フェイズシフト装甲**：一定量内免疫实弹；超阈值 **フェイズシフトダウン**（机体灰化）。
- **陽電子リフレクター / エネルギー偏向装甲**：光束反射/偏转（角度与耐久限制）。
- **トランスフェイズ装甲**：Down 外观不明显（如デスティニー）。
- **ミラージュコロイド**：隐身/迷彩，降低锁定与命中。

### 1.3 复刻建议原则

1. **机制层**（资源循环、武装、装甲、换装/パージ）→ 尽量 1:1。  
2. **数值层** → 表驱动，对照录像/攻略回归。  
3. **体验层**（镜头、锁敌、输入、UI）→ 可在不改机制前提下优化。

**建议采纳的 REMASTERED 改进**：スタンダード/クラシック双锁敌模式；PS 残量与状态 UI；多控制器映射 + SP 一键；教程与 HUD 分层。

**手感红线（验收用）**

- 锁敌切换在混战中 3 秒内可稳定切到任务目标或最近威胁。
- チャージ射撃装填与原作同类机体体感一致（以代表机体基准用例回归）。
- オーバーヒート惩罚为「节奏刹车」而非长时间瘫痪。
- パージ决策不可逆，UI 与状态同步无穿帮。
- Guard 与チャージ共键时的误触率可通过输入缓冲/配置降至可接受范围。

### 1.4 战斗模块 Must / Should / Later

| 优先级 | 模块 |
|--------|------|
| **Must** | 锁敌（至少スタンダード）；HP/SP/BOOST；主/副/格闘；ガード；ブースト与过热；チャージ三连；至少 1 机体 SP；僚机默认 AI + 四类指示；PS 装甲代表实现；总弹数/装填数据驱动；击坠/再出击最简版 |
| **Should** | 多主兵装切换；換装/変形代表机体；マルチロック/多重ロック；予測射撃/狙撃；パージ不可逆；第二批特殊装甲；コンビネーション SP（2–3 对）；补给集装箱；锁敌 UI 增强；环境战差异 |
| **Later** | 全机体全武装；高级僚机 AI；战斗回放/逐帧判定可视化；本地分屏/联机；完整海战等特殊地形 |

### 1.5 战斗垂直切片验收

1. **宇宙环境**，玩家 **ストライクダガー**（或同级教学机体）+ 默认 CPU 僚机。  
2. 击败含 **PS 装甲** 与 **实弹/光束混合** 编队。  
3. 演示：锁敌切换 → 主副射击 → 装填与总弹数 → 集装箱补给 → チャージ射撃装填 → 格闘收尾。  
4. 至少一次 **オーバーヒート** 并恢复；一次 **SP アタック**；僚机 **射撃/SP 指示**。  
5. 烟雾或重要目标切换验证锁敌丢失与右摇杆上切目标。

### 2.1 设计目标

| 维度 | 目标 |

| **扎夫特** | 调整者军事线 | 吉恩/盖茨系、实验机、精英机 |

|--------|----------|------|
| **C.E.71** | SEED | 新游戏默认 |

REMASTERED 改进为 **Must 对齐**（非可选）：**同一存档可切换势力路线** 游玩；机体入手与部分解锁条件 **缓和**——粉丝复刻默认 **对齐 REMASTERED**，而非回退 Vita 周目制。

### 2.2 战略地图与任务解锁

节点式战略地图：`Locked → Available → Cleared → (Optional) Farmable`。

典型解锁条件组合：

1. 主线序号  
2. 阵营 + 时代  
3. 机体/机师/搭档持有  
4. 评价门槛（S 评价隐藏 EX）  
5. 全局 Flag（Another Arc、来宾状态）

任务类型：主线、支线、训练、防卫/护送等。

### 2.3 Another Arc / EX / Hyper Boss

- **Another Arc**：关键节点二选一/多选 → 写入 `flag` → 差分战斗与短剧情。  
- **EX**：高难度/番外；独立掉落表；首通 vs 重复刷分离。  
- **Hyper Boss**：超规格多阶段 BOSS；失败可重试且不锁死主线；Should 提供练习模式。

### 2.4 搭档、点数强化、技能与来宾

**搭档（パートナー）**：战前指定僚机机师/机体；搭档技能与机体绑定；部分任务强制搭档。

**点数强化**：任务结算 CP → 消费提升机师基础能力（攻击/防御/机动/SP 等）；上限与递增成本；与 **机体コスト**（强化越高再出击次数越少）联动。

**机师技能**：被动（最多 2 槽，部分不可拆卸）+ **アディショナル**（低 HP 自动触发）；原创驾驶员可配点；**ゲストパイロット** 技能固定或剧情专用。

**来宾机师**：临时操控 / AI 友军 / 强制机体；条件满足后可入搭档池或解锁机体。

### 2.5 战役养成 Must / Should / Later

|------|------|--------|-------|

## 四、技术架构

### 4.1 技术选型（推荐）

| 层级 | 选型 | 说明 |
|------|------|------|
| 引擎 | **Godot 4.x**（4.3+） | MIT；Switch 导出有经验；迭代快 |
| 主语言 | **GDScript 2** | 默认全栈 |
| 性能热点 | C# 或 GDExtension | profiling 后局部引入 |
| PC | Steamworks + Windows x64 优先 | 可选 Linux |
| Switch | Godot Switch 导出 | 需任天堂开发者资格 |
| 数据 | JSON/YAML + 运行时 Resource 缓存 | 见 `data/` |
| 3D | Blender → glTF → Godot | 规范见 `docs/art-pipeline.md`（待建） |
| CI | GitHub Actions（PC）；Switch 私有构建 | 密钥不进公有 CI |
| 测试 | GUT + 战斗输入回放 | 性能基准场景 |

备选：Unity（许可与费用）、Bevy（Switch 生态不成熟）。**默认 Godot 4**，除非团队已有强 Unity 产能。

### 4.2 运行时架构

```text
Presentation (UI/HUD/输入)
    ↓
Game Flow (战役进度/出击/结算/存档)
    ↓
Mission │ Combat │ Progression
    ↓
Data Layer (units/missions/skills + 存档)
    ↓
Platform (Steam/Switch 抽象)
```

- **LockOnSystem** 独立模块：候选筛选、硬/软锁定、相机混合。  
- 任务 **声明式触发器** + 可选脚本钩子。  
- 存档仅序列化进度与养成，不序列化节点路径。

## 八（原稿）、待用户拍板的三项决策（已由 ADR-0001 取代）

以下原「待拍板」内容保留作历史参考；**均已按默认选项锁定**。

### 决策 1：对外身份与 IP 合规边界

**问题**：商店页、README、游戏内如何命名与表述？是否接受「SEED / Battle Destiny」字样？是否寻求任何官方沟通？

| 选项 | 利弊 |
|------|------|
| A. 中性粉丝名 + 副标题「SEED 启发」 | 商标风险较低；发现成本较高 |
| B. 保留「SEED 激斗命运复刻」作为主名 | 粉丝识别度高；下架/DMCA 风险升高 |
| C. 仅私有构建，不公开展示/分发 | 风险最低；无法形成社区协作 |

**默认建议**：A + 显著非官方免责声明；M2 前至少一次 IP 法务咨询（即便选择 C）。

### 决策 2：引擎与技术栈

**问题**：是否采纳本方案的 **Godot 4 + GDScript** 默认栈？

| 选项 | 利弊 |
|------|------|
| A. Godot 4（推荐） | MIT、迭代快、双平台可行；Switch 需开发者资格与导出经验 |
| B. Unity | 生态成熟；许可费与运行时条款需评估 |
| C. 其他（Bevy/自研） | 长期成本高或 Switch 不成熟 |

**默认建议**：A；M1 结束前用 profiling 决定是否局部 C#/GDExtension。

### 决策 3：M2 垂直切片的内容剖面

**问题**：第一条可玩闭环聚焦哪个 **势力 × 时代 × 机体规模**？

| 选项 | 利弊 |
|------|------|
| A. 大天使号 × C.E.71 × 18 机 | 交汇剧情与来宾测试价值高（**推荐**） |
| B. 地球联合 × C.E.71 × 12 机 | 工期更短；换装/变形覆盖略少 |
| C. 扎夫特 × C.E.73 × 15 机 | 验证 73 机体与难度曲线；71 管线后置 |

**默认建议**：A；若工期极紧则 B，但须在 M3 补全机制代表机体。
