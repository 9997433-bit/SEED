# Nintendo Switch 可行性 Spike（M0）

> **文档性质**：粉丝向非商业复刻项目的技术可行性调研（规划稿）  
> **状态**：M0 交付，结论为 **条件性可行（Conditional Go）—— 但当前被商务与法务阻塞**  
> **最后更新**：2026-08-25  
> **对照基准**：Steam 正式版 REMASTERED（[AppID 1857740](https://store.steampowered.com/app/1857740/)），官方公开规格中 Switch 版 **最高 30fps**

## 0. 保密边界（先读）

本文 **只使用公开可获取的信息**：引擎官方文档、公开博客与新闻、任天堂公开的开发者门户页面、商店页公开规格。

**本文不含、也永远不会含**：

| 不含内容 | 原因 |
|----------|------|
| Nintendo SDK / NintendoSDK 头文件、API 名称、工具链细节 | 受 NDA 约束，且仓库为公开仓库 |
| devkit 硬件规格、实测跑分、系统固件行为细节 | 受 NDA 约束 |
| Lotcheck（认证）条目原文与内部检查表 | 受 NDA 约束 |
| 主机内存/带宽的官方数字 | 公开报道口径不可作为工程依据；官方数字在 NDA 文档中 |
| 任何密钥、证书、签名工具、devkit 配置文件 | 红线：不入公有 Git、不入公有 CI |

获得开发者资格后，NDA 覆盖的内容 **一律放私有仓库**，本文只保留「公开可说」的部分与指向私有文档的占位链接。

## 1. 结论摘要

| 问题 | 结论 |
|------|------|
| 技术上能不能做？ | **能**。Godot 4 工程移植到 Switch 属于业界已验证路径（需通过被授权的商业移植方案），本项目的 M0 骨架未使用任何阻断移植的特性 |
| 现在能不能做？ | **不能**。缺 **开发者资格 + devkit**，且引擎侧 Switch 支持不在 Godot 官方开源发行版内 |
| 该不该公开发行？ | **默认不做**。无 IP 授权前提下，公有 eShop 上架属 REMAKE-PLAN 明确的 **非目标**；Switch 仅作 **自有 devkit 上的技术验证** 与 **设计约束来源** |
| M0 该交付什么？ | 本文 + 把 Switch 约束写进 PC 侧工程（性能预算、输入、帧率档），而不是投入平台实现 |

**一句话**：Switch 在 M0 的角色是 **约束提供方**，不是 **构建目标**。M4 之前不安排任何平台代码。

## 2. 公开事实基线

| 事项 | 公开信息 | 出处性质 |
|------|----------|----------|
| Godot 官方发行版是否含 Switch 导出 | **不含**。Godot 开源发行版不提供主机（Switch / PlayStation / Xbox）导出模板 | Godot 官方文档「Console support in Godot」 |
| 为什么不含 | 主机 SDK 受 NDA，与 Godot 的 MIT 开源分发条款不兼容 | 同上 |
| 可行路径 | 通过 **被主机厂商授权的第三方移植服务商 / 商业授权版引擎** 获取主机后端；或自行取得授权后内部维护移植分支 | 同上（Godot 官方列出「third-party console porting」路径） |
| 开发者资格 | 任天堂开发者门户（Nintendo Developer Portal）公开接受申请，需通过审核后方可购买 devkit 与获取 SDK | 任天堂公开页面 |
| 对照产品的 Switch 规格 | REMASTERED 官方规格：Switch **最高 30fps**；Steam 推荐 60fps | Steam 商店页 / 官方站点公开文案 |
| 分发形态 | eShop 上架需通过发行审核与内容分级；粉丝作品在无授权时不具备上架资格 | 常识性公开约束 |

> 补充：Godot 4 主线的渲染后端为 Vulkan（Forward+ / Mobile）与 OpenGL（Compatibility）。Switch 的原生图形 API 不是这三者中的任何一个，因此 **图形后端必须由被授权的移植方案提供** —— 这是「不能自己 DIY 一个 Switch 导出」的技术根因，也是本项目 **不在公有仓库放任何平台后端代码** 的原因。

## 3. 阻塞项（Blockers）

| ID | 阻塞项 | 影响 | 解除条件 | 现状 |
|----|--------|------|----------|------|
| **B-1** | 无 IP 授权 | 公有 eShop 上架不可行；商业化不可行 | 取得权利方授权（默认不追求） | 永久阻塞（按 ADR-0001 接受） |
| **B-2** | 无任天堂开发者资格 | 拿不到 SDK / devkit / 认证通道 | 通过开发者门户申请并获批（需实体信息与项目说明） | 未申请 |
| **B-3** | Godot 官方无 Switch 后端 | 无法用开源工具链出包 | 走被授权的第三方移植方案，或自建授权分支 | 未启动（依赖 B-2） |
| **B-4** | NDA 与公有 CI 冲突 | 平台代码/密钥不能进公有仓库与 GitHub Actions | 平台层放私有仓库 + 私有 runner；本仓库仅留 `platform/switch/` 接口占位 | 已按此设计 |
| **B-5** | 渲染后端选型未定 | 当前工程用 `gl_compatibility`，移植时可能需切 Forward+/Mobile 并重做材质 | M1 性能基线后决策（见 §5） | 未决 |
| **B-6** | CJK 字体授权 | Switch 包内需自带字体；当前 PC 工程依赖系统字体 | 选用可再分发字体（如 SIL OFL 的思源黑体/Noto Sans CJK）并登记 NOTICE | M3 本地化管线处理 |

**B-1 与 B-2 是硬阻塞**：在两者解除前，任何 Switch 平台实现工作都是沉没成本。

## 4. 技术风险清单（公开层面可评估）

| 域 | 风险 | 我方缓解（不依赖 NDA 信息） |
|----|------|------------------------------|
| **内存** | 掌机级设备的可用内存远小于 PC；纹理与网格是主要占用 | 自设预算：运行时纹理 ≤ ~1.5 GB、同屏机体 ≤ 9（REMAKE-PLAN §4.5）；资产管线强制 LOD 与纹理上限（`docs/art-pipeline.md`） |
| **帧率** | 对照产品 Switch 侧为 30fps 上限 | 战斗逻辑与物理 **不绑定帧率**；30/60 双档在 M1 建立并在 PC 上双档回归 |
| **渲染后端** | Switch 后端由移植方案提供，特性集可能落后于 Forward+ | 避免依赖 Forward+ 独占特性（SDFGI、体积雾等）；着色器走 `gl_compatibility` 可跑的子集 |
| **加载** | 卡带/内置存储读取慢于 NVMe | 出击加载异步化 + 进度条（已在 REMAKE-PLAN §4.5 约束）；避免主线程同步大资源载入 |
| **输入** | Joy-Con 分离/合体、掌机/主机模式切换、控制器热插拔 | 输入层以 Godot Action 抽象；M1 起禁止在玩法代码里读死键位；按键提示图标走数据驱动 |
| **分辨率** | 掌机 720p 与主机 1080p 双档，UI 需可读 | UI 用 `canvas_items` 拉伸 + 最小字号规则；在 PC 上以 1280×720 窗口做可读性回归 |
| **存档** | 主机存档配额小且写入需遵循平台规范 | 存档只序列化进度与养成（REMAKE-PLAN §4.2），保持 KB 级；不写节点路径 |
| **认证** | 主机认证对暂停/恢复、错误提示、控制器断连等有硬性要求（具体条目 NDA） | 架构上预留「暂停/恢复」与「控制器丢失」全局事件，PC 侧也实现，避免移植期返工 |
| **本地化/分级** | 上架需分级与本地化合规 | 与 B-1 一同视为非目标 |

## 5. M0/M1 可执行的替代验证：Switch 约束模拟档

在 devkit 不可得的情况下，**可行性验证依然可以做**，方法是在 PC 上跑一个「按 Switch 约束设限」的配置档，把约束违规变成可回归的失败：

| 约束 | 模拟方式（全部在公开工具链内） |
|------|-------------------------------|
| 30fps 上限 | `--max-fps 30`（CI 已用同族参数跑主场景，见 `.github/workflows/build-pc.yml`） |
| 掌机分辨率 | 1280×720 窗口 / viewport 覆盖 |
| 手柄唯一输入 | 关闭键鼠 Action 映射的档位 |
| 同屏机体 ≤ 9 | 战斗场景生成上限（M1 战斗系统落地时加断言） |
| 纹理预算 | 资产导入检查：单张 ≤ 2K、机体集合总量上限（M3 资产 CI） |
| 内存水位 | `Performance.get_monitor(MEMORY_STATIC)` 采样 + 基线报告（M1 性能基线） |

**M1 交付建议**：把上述项固化为一个 `switch_sim` 运行档与一份基线报告，作为「Switch 可行性」的持续证据，而不是一次性文档。

## 6. 若 B-1/B-2 解除，后续步骤（备忘）

1. 申请并获批开发者资格 → 签署 NDA → 建立 **私有** 平台仓库与私有 runner。  
2. 评估被授权的移植方案（商业移植服务 vs 授权引擎分支），确认其对 Godot 4.3+ 与本项目渲染档的支持。  
3. 在私有仓库落地 `platform/switch/` 的真实实现；公有仓库只保留接口与文档占位。  
4. 建立 devkit 上的性能基线（30fps 档、内存水位、加载时长），与 §5 的 PC 模拟档对表。  
5. 认证前自检（条目见私有文档）。

> 上述第 2–5 步的产物 **全部不进入本公开仓库**。
